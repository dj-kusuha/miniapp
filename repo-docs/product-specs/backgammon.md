# Backgammon

## Summary

ブラウザだけで遊べるバックギャモン。対戦相手は、勝敗のみを報酬に自己対局で
学習したニューラルネット AI（TD-Gammon 方式）。

**AI とルールエンジンは外部リポジトリ
[dj-kusuha/backgammon_engine](https://github.com/dj-kusuha/backgammon_engine)
で開発している。** ただし english-typing と違い、**そちらは Python で
サーバ実行前提**なので、成果物をそのまま置けない。**JavaScript へ移植した
ものを `docs/backgammon/` に配置する。**

## Users

- バックギャモンを指したい人（ルールを知っている前提）
- 学習した AI がどのくらい打てるのか触って確かめたい人

## Problem

engine 側にも Web フロントエンド（`play_web.py`）はあるが、**Python サーバが
必要**でローカルでしか動かない。URL を開くだけで遊べる場所が無い。

## Goals

- URL を開くだけで、インストールもサーバも無しに 1 局遊べる
- AI は engine の同梱モデル（`models/td_gammon.json`）と**同じ手を選ぶ**
- ルール（合法手生成・ベアオフ・バー・ギャモン / バックギャモン判定）が
  engine と一致する

## Non-Goals

- **ダブリングキューブ**（engine 側には実装があるが、初版では扱わない）
- **3-ply 以上の先読み。** engine の実測で 1 手 5.6 秒かかるため
- 対人戦・通信対戦・棋譜の保存・アカウント
- 盤面の反転表示（engine 側の既知の制約と同じく White 視点固定で始める）

## Core Flow

1. トップで AI の強さを選んで開始（**人間は常に White**。盤は White 視点
   固定なので、色を選ばせると盤が読みにくくなる）
2. サイコロを振る → 動かす駒をクリックして着手（出目は左から順に使う）
3. AI が応手 → 決着まで繰り返す
4. 勝敗（シングル / ギャモン / バックギャモン）を表示して、もう 1 局へ

## UI Notes

- モバイルファースト。360px 幅で盤面が破綻しないこと
- 操作はクリック。駒をクリックすると出目キューの手前（左）の目を即座に使って
  動かし、次に動かせる駒をハイライトする（移動先を別途クリックさせない）。
  ドラッグ&ドロップにしない
- 盤は実物に寄せる。ポイントは三角形、バーは中央に幅を持たせ、右端に
  ベアオフ用のトレイを置く（黒は上段側、白は下段側）
- 駒 5 個を積んでも中央の帯を越えないよう、盤は実物より縦長にしてある
- サイコロは中央の帯に置く。自分は右半分、AI は左半分（相手から見て右）。
  **手番中の側だけ表示し、使い切ったら片付ける**
- 出目をクリックすると使う順番を入れ替えられる（ゾロ目のときは無効）
- 「サイコロを振る」は自分のダイスと同じ位置（盤の右半分中央）に出す。
  操作する場所を 1 箇所にまとめる。「もう一局」などは盤の下のまま
- AI の着手は 1 手ずつ間を置いて見せる。ダンス（動かせない出目）のときも
  出目を見せる時間を必ず取る。「気づいたら自分の番」になるのを避ける
- 棋譜は PC 幅では盤の右、狭い画面では盤の下に折りたたむ

## ローカルでの動かし方

ES modules を使うので `file://` では動かない（import が CORS で止まる）。

```
cd docs/backgammon && python3 -m http.server 8000
```

でサーバを立て、`http://localhost:8000/` を開く。

## Technical Notes

### スタック

- 素の HTML / CSS / JavaScript（[FRONTEND.md](../../FRONTEND.md) の
  「単一ページで完結するなら素の JS を優先」に従う）
- **外部 API なし。** すべてブラウザ内で完結する

### AI の推論

同梱モデルは **198 → 80 → 5 の 3 層 MLP**（約 348KB の JSON）。
推論は**行列積 2 回とシグモイド 2 回**だけで済むので、依存なしで書ける。

```
入力 198 次元 → 隠れ 80（sigmoid）→ 出力 5（sigmoid）
出力は [勝ち, ギャモン勝ち, バックギャモン勝ち, ギャモン負け, バックギャモン負け]
着手は equity = 2·P(win) + P(wg) + P(wbg) − P(lg) − P(lbg) − 1 が最大の手を選ぶ
```

**2-ply の先読みまで入れる。** engine で 1 手あたりの評価回数を実測した
（2026-08-18、40 局面）:

| 先読み | 評価回数 / 手 | 積和 | 強さ（固定ベンチマーク） |
| --- | --- | --- | --- |
| 0-ply | **21 回** | 約 34 万 | 17.5 mEMG |
| **2-ply** | **2,103 回** | 約 3,400 万 | **10.4 mEMG** |
| 3-ply | — | — | 1 手 5.6 秒（重すぎる） |

**2-ply でも 1 手あたり 3,400 万積和なので、ブラウザで数十 ms に収まる
見込み。** 候補手を絞る move filter が効いていて、素朴に全展開したときの
1/30 で済んでいる。強さは 0-ply の 17.5 に対し 10.4 と大きく違うので、
**入れる価値が大きい。**

> 初版で先に 0-ply を動かし、**実測してから** 2-ply を有効にする。
> 見積りが外れたときに「重くて遊べない」状態を配信しないため。

### ルールエンジンの移植

engine 側の Python が正本。**同じ移植を C# で一度やっており
（`csharp/`）、Python との一致を検証する
パリティテスト（`tests/test_runner.py` と `csharp/tools/export_parity_fixtures.py`）
がある。** JS 移植でも同じ仕組みを使い、**engine が出力する固定局面の
期待値と突き合わせて一致を確認する。**

### 着手 UI と合法手の対応づけ

**`Move.singles` の並びを「操作順」として使ってはいけない。** `generateMoves` は
同じ最終盤面になる手順を 1 つに畳むので、残った並びだけを見ると「順番が違う
だけの合法な手」がクリックできなくなる（初期実装の不具合。全 36 通りのロール中
9 通りで移動元を取りこぼしていた）。

`rules.js` の `nextSingles()` は並びに依存せず、**残りの出目で合法な終了盤面
（`generateMoves` が返した最終盤面の集合）に到達できるか**で次の 1 手を判定する。
最大消費・大きい目優先の規則は `generateMoves` 側で適用済みなので、この判定に
それらを再実装しない。

### 棋譜の書き出し（gnubg / Jellyfish の .mat）

gnubg の読み込み側（`import.c`）は書式に厳しく、**gnubg 自身の書き出しに
合わせる**（`OutputMove` の `"%3d) "` + `"%-27s "`）。実際に踏んだ落とし穴:

- プレイヤー行は `名前 : スコア` の**コロンが必須**。無いと `ImportGame` が
  即 `return 0` して対局がまるごと読み飛ばされる
- 手数の区切りは `1)` の**閉じ括弧**。`strchr(szLine, ')')` で左列の開始を
  探すため、`1:` にすると列の分割がずれて壊れる
- 着手欄は `65: ...`（1〜6 の 2 桁 + コロン + 空白）。ダンスは出目だけ書く
- キューブ非対応なので `0 point match`（マネーゲーム）で正しい。
  `nLength < 0` だけが弾かれ、0 は正常値

### モデルの同期

engine 側でモデルは更新され続ける（2026-08-18 に 319,100 → 540,000
エピソードへ差し替え、固定ベンチマークで 25.2 → 17.5 mEMG）。

初版は **english-typing と同じ手動同期**とする。engine 側で
`models/td_gammon.json` を更新したら、このリポジトリへコピーしてコミットする。
自動化は Open Questions に置く。

## Acceptance Criteria

- https://miniapp.kusuha.com/backgammon/ で 1 局を最後まで遊べ、
  コンソールエラーが出ない
- トップページ（`docs/index.html`）の一覧から遷移できる
- **engine が出力したパリティ用の固定局面について、JS 側の合法手集合と
  AI の選ぶ手が Python 側と完全に一致する**
- 360px 幅とデスクトップ幅で盤面が破綻しない
- キーボードだけで着手できる
- **合法な移動元がすべてクリックできる**（着手順の畳み込みで取りこぼさない）
- 書き出した .mat を gnubg が読み込める

## Open Questions

- **モデル同期の自動化。** engine 側の Release に公開して取りに行くか、
  engine の CI からこのリポジトリへ PR を出すか。当面は手動
- **2-ply がブラウザで実際に何 ms か。** engine 側の評価回数（2,103 回/手）
  からは数十 ms と見込んでいるが、JS の実測はまだ
- **ダブリングキューブをいつ入れるか。** engine 側には実装がある
- 盤面反転（Black 視点）を初版に入れるか
